# Sprint r-7 — `sc-decision-schema` crate and model catalog

Owner decisions 2026-11-07 (plan.md "Owner decisions 2026-11-07", items 1–3,
5, 6 and 7). Governing ADRs: ADR-SAG-0030 and ADR-SAG-0031's "Storage schema"
subsection, both inserted **Proposed** by the plan PR and flipped by this
sprint (except the ADR-SAG-0030 `jev::v1` bullet, which r-5 flips).

## Outcome

Every decision type has one home, `sc-decision-schema`, a published,
data-only crate above `sc-agent-types`. It holds the versioned decision
schema (question and answer payload), the Haiku/Luna input/output mapping
on that schema, the per-model-family variant mechanism for future local
decision models, and the session-log SQLite schema with its `fields{}`
projection. `sc-agent-types` keeps what every agent kind shares (ids,
errors, secrets, git, cancel, the observability port, the backend catalog)
and gains a model catalog (open `ModelId`, `latest(alias)`, overridable from
`check.toml`), the `SendTrace` handle and `ProjectLabel`. Backends report
and send their configured model and pass the request's `SendTrace` to the
one `sc-agent-http` exchange as a required argument (recording the digest
is r-6). The Jev request/response structs
(`jev::v1`) are r-5's. No wire byte, digest, stdout golden or session
document byte changes.

## API clarifications (PR 32 QA, binding for r-7)

- `SessionLogRow::try_from_fields` refuses a `schema_version` other than
  `SESSION_LOG_SCHEMA_VERSION` (INPUT_INVALID; hint names the supported
  version and "written by a newer sc-agent"); covered by
  `test_unknown_or_missing_key_rejected`.
- `JudgeBackend` stays open (ADR-SAG-0009). Its semver promise is the
  additive rule: new methods get default bodies. It stays dyn-compatible
  (`&self` receivers, no generic methods, no `Self` in signatures); the
  rustdoc and the crate README say both.
- `RowContext.repo` stays absolute path text (owner decision). A non-UTF-8
  byte is replaced; two such repos can share one `answers_by_repo_project`
  key, documented on the field.
- `ModelDescriptor::model()` uses `expect` (M-PANIC-ON-BUG); the invariant
  is proven by `test_known_models_roundtrip`.
- `AnswerId::from_str` and `ModelId::from_str` errors carry fix hints (use
  the logged `answer_id`; use a non-empty model string or an alias), and
  the acceptance rows assert the hint.
- `test_latest_alias_lookup` also asserts every `released` value is a valid
  `YYYY-MM-DD` date.
- D9 also flips the ADR-SAG-0030 "Per-API modules and crate naming" bullet
  to `(Active, r-7)`.

## Layering (decided; ADR-SAG-0030)

Module layout: one module per decision API. `jev::v1` lands in r-5 and is
carried unchanged; `decider::`, `laya::` and `kev::` are reserved. r-7 adds
no per-API module.

```text
sc-agent-types        ids, JevError/ErrorCode, ScAgentErrorResponse, BackendId + BACKENDS,
  (below)             ModelId/ModelFamily/ModelAliases, Sha256Digest, CancelToken, SendTrace, ProjectLabel,
                      ResolvedApiKey (secret), observability::v2 port (obs), git (git),
                      schema::subjects
sc-decision-schema    QuestionId, ChoiceId, Question, ChoiceAnswer, CanonicalJudgePayload,
  (above)             PayloadBundle, canonical_json_bytes, QuestionAnswer, DecisionAnswers,
                      JudgeOutcome, JudgeRequest, LlmWireContext, JudgeBackend,
                      BackendCapabilities, Attestation, BackendAttestation, EqualInputRecord,
                      MultiBackendMode, DecisionSchemaId + versions, llm::v1, variants,
                      session_log; test_util::MockJudgeBackend (test-util); jev::v1 (r-5)
```

- **Data-only** means the dependency set: `sc-agent-types`
  (`default-features = false`, core only), `serde`, `serde_json`, enforced by
  the boundary manifest (D1.3). The `JudgeBackend` trait moves with the
  types its signatures name (a trait cannot sit below `JudgeOutcome`); it
  adds no dependency.
- **Moved, not copied.** `git mv` the `judge` and `payload` modules,
  `QuestionId`, `ChoiceId` and `test_util`; `sc-agent-types` re-exports none
  of them (a re-export would be a Cargo cycle). Its `judge` and `test-util`
  features are deleted (nothing is published, so no deprecation path).
  Every call site imports from `sc_decision_schema`.
- **`BackendId` vs `ModelId`.** `BackendId` is how we call (Jev API,
  Anthropic API, OpenAI API); `ModelId` is which model. Today's id spellings
  `anthropic_haiku` / `openai_luna` are kept as is (serde, CLI, `check.toml`
  compatibility); renaming them is not in scope.

### D3 — Versioning (REQ-SAG-0142)

   `KNOWN` and refuses any other with `INPUT_INVALID` (input documents) or
   `RESPONSE_INVALID` (backend output), fix hint naming the supported
   versions. Additive optional fields keep the version; a removed, renamed
   or retyped field, or a changed meaning, bumps it.

   `CanonicalJudgePayload` and never part of `PayloadBundle::bytes()`, so
   `prompt_sha256` and the Rust/Python cross-implementation fixture stay
   byte-identical. It is carried by the sc-agent-owned wrappers around the
   payload: the session-log row (`decision_schema`, D6) and, from r-6, the
   session document. It is not sent to Jev, Anthropic or OpenAI (their
   bodies follow their own schemas; Jev's is r-5's `jev::v1`).

### D6 — Session-log storage schema and `fields{}` projection (REQ-SAG-0146; ADR-SAG-0031 "Storage schema")

Owner decision 2026-11-07 item 5: the SQLite schema is authoritative; the
JSONL "projection" is the `fields{}` object of one sc-observability v2 log
line (ADR-SAG-0013: no bespoke writer); a loader reads `fields{}` into the
tables. r-7 defines the schema and types; **r-6 emits them**. No SQLite
dependency or writer lands in A.1.

1. `crates/sc-decision-schema/src/session_log/schema.sql` (the DDL,
   `pub const SESSION_LOG_DDL: &str = include_str!(...)`),
   `SESSION_LOG_SCHEMA_VERSION: u32 = 1`, `COLUMNS` (the projection's key
   list, in order), `RowContext` (the values every row carries),
   `SessionLogRow` (private fields, one constructor per outcome:
   `SessionLogRow::ok(RowContext, DecisionAnswers)` and
   `SessionLogRow::failed(RowContext, ErrorCode)`), `SendOutcome { Ok,
   Failed }` (serde `ok` / `failed`), `SessionLogRow::to_fields()` and
   `SessionLogRow::try_from_fields(&Map)` (unknown key, missing key or wrong
   type is `INPUT_INVALID`).

   ```sql
   -- schema_version 1. Authoritative.
   -- Every column that can vary between two sends of one session or one
   -- prompt lives on `answers`, so the loader's INSERT OR IGNORE loses nothing.
   CREATE TABLE sessions (
     session_id          TEXT PRIMARY KEY,        -- ULID (r-6)
     session_created_at  TEXT NOT NULL            -- RFC 3339 UTC, ms; fixed per session
   );
   CREATE TABLE questions (
     prompt_sha256    TEXT PRIMARY KEY,           -- SHA-256 of the canonical payload bytes
     question_ids     TEXT NOT NULL,              -- JSON array, payload order (fixed by the digest)
     first_seen_at    TEXT NOT NULL               -- loader: ts of the first row for this digest
   );
   CREATE TABLE answers (
     answer_id        TEXT PRIMARY KEY,           -- ULID, one per send
     schema_version   INTEGER NOT NULL,           -- SESSION_LOG_SCHEMA_VERSION of the row
     session_id       TEXT NOT NULL REFERENCES sessions(session_id),
     prompt_sha256    TEXT NOT NULL REFERENCES questions(prompt_sha256),
     decision_schema  TEXT NOT NULL,              -- DecisionSchemaId of this send, e.g. canonical.v1
     repo             TEXT NOT NULL,              -- main repo root, else calling folder (absolute)
     project          TEXT,                       -- caller text for this send; NULL when absent; not scrubbed
     request_sha256   TEXT,                       -- SHA-256 of the exact body sent; NULL when no body was built
     ts               TEXT NOT NULL,              -- RFC 3339 UTC, ms; when the send finished
     operation        TEXT NOT NULL CHECK (operation IN ('judge','ask')),
     backend          TEXT NOT NULL,              -- BackendId: how we called
     model_id         TEXT NOT NULL,              -- ModelId string: which model (never NULL)
     send_outcome     TEXT NOT NULL CHECK (send_outcome IN ('ok','failed')),
     error_code       TEXT,                       -- ErrorCode id; NOT NULL iff failed
     answers_json     TEXT,                       -- DecisionAnswers JSON; NOT NULL iff ok
     CHECK ((send_outcome = 'ok') = (error_code IS NULL)),
     CHECK ((send_outcome = 'ok') = (answers_json IS NOT NULL))
   );
   CREATE INDEX answers_by_question_model ON answers (prompt_sha256, model_id);
   CREATE INDEX answers_by_request        ON answers (request_sha256);
   CREATE INDEX answers_by_repo_project   ON answers (repo, project);
   ```

2. **Projection.** One send is one log line; its `fields{}` object has
   exactly the `COLUMNS` keys: `schema_version`, `answer_id`, `session_id`,
   `session_created_at`, `repo`, `project`, `prompt_sha256`,
   `decision_schema`, `question_ids`, `request_sha256`, `ts`, `operation`,
   `backend`, `model_id`, `send_outcome`, `error_code`, `answers_json`.
   Nullable columns are present with `null`. `question_ids` is a JSON array
   and `answers_json` a JSON object (the SQLite columns hold the same JSON as
   text). The key is `send_outcome`, not `outcome`, so it never collides with
   the v2 envelope's own `outcome`. `ts` is the row's time; the envelope
   `timestamp` is write time and the loader ignores it.
3. **Loader rule and losslessness.** A loader inserts `sessions` and
   `questions` with `INSERT OR IGNORE` (deriving `first_seen_at` from `ts`)
   and `answers` with `INSERT`. This is lossless because the two
   deduplicated tables hold only values fixed by their key
   (`session_created_at` by the session, `question_ids` by the canonical
   bytes); `repo`, `project` and `decision_schema` are per send, on
   `answers`, so two sends of one session with different `project` values
   both keep theirs.
4. **Rules.** No secret, payload text, prompt text or raw response body in
   any column (NFR-SAG-0002); `answers_json` holds only typed answers.
   `repo` is the only path column. `project` is caller text, stored as
   given and not scrubbed, and always a valid `ProjectLabel` (D8.4). Adding or renaming a column, or changing a type
   or nullability, bumps `SESSION_LOG_SCHEMA_VERSION` with a migration note.
5. `docs/sc-decision-schema/session-log-schema.md`, titled "Session log
   storage schema (SQLite, authoritative)", points to `schema.sql` (it does
   not copy the DDL or restate its column comments) and holds the loader
   rule (item 3) and the migration notes.
6. Golden fixture `tests/fixtures/decision-schema/session-log/fields.jsonl`:
   one `fields{}` object per line — an `ok` judge, a `failed` judge with a
   body (`request_sha256` set), a `failed` judge before any body was built
   (`request_sha256: null`, `model_id` set), an `ok` ask, a row with
   `project: null`, and an `ok` ask in the first row's session with a
   different `project`.

### D8 — Send-trace seam and `ProjectLabel` (REQ-SAG-0613 seam, REQ-SAG-0146)

1. `sc_agent_types::SendTrace` (core, `trace.rs`, next to `CancelToken`): a
   cloneable handle with `record` (first write wins) and `request_sha256`.
2. The trace is per send, never carried on the cloneable `JudgeRequest`:
   `JudgeBackend::judge(&self, req: &JudgeRequest, trace: &SendTrace)`

   `judge` and `ask` call and keeps a clone to read after the call returns.

   `Transport` trait is otherwise unchanged. `sc-jev` (`client/mod.rs`) and
   `sc-jev-backends` (`backend.rs`) pass `trace.clone()` and build bodies

   recording in `send_with_busy_retry` and reads it into the row. This gives
   r-5 and r-6 disjoint files in wave 6.
4. `sc_agent_types::ProjectLabel` (core, `ids.rs`): UTF-8, at most 256
   bytes, no control characters, else `INPUT_INVALID` whose fix hint states

## Implementation notes

Choices where the sprint doc is silent (all conservative):

- `ModelDescriptor` release dates are `jev-1.13.0` 2026-06-01, `claude-haiku-5-5`
  2026-09-01, `gpt-6-luna` 2026-08-01. The sprint names no dates; they only order
  rows within one alias and must be corrected if a real date matters.
- `AnswerId::new()` builds its own ULID text (48-bit millisecond clock plus 80
  random bits from the existing `uuid` dependency, Crockford base32); r-6
  replaces the body with `ulid::Ulid`. `from_str` accepts only 26 uppercase
  Crockford characters with a first character at most `7`.
- `JevClientConfig::try_new` takes a `ModelId` first argument; `from_toml` and
  `packaged()` use the catalog Jev model, and a stale `model` key in `jev.toml` is
  `CONFIG_INVALID` (`deny_unknown_fields`). `JevClient` and the Haiku/Luna
  backends gain `with_model`.
- `JudgeBackend::model_id` for `JevClient` is in `client/mod.rs`, not `check.rs`
  (the trait impl lives there).
- `BackendRegistry` keeps `from_env` / `from_resolver` (catalog models) and gains
  `from_env_with_models` / `from_resolver_with_models`. `CheckSpec` gains a public
  `models: ModelAliases`; `PreparedRun::models()` reports the resolved aliases:
  `RunConfig::models` wins over the check's `[models]`, which wins over the catalog.
  `ask` uses `RunConfig::models` only. `ModelAliases` derives `PartialEq, Eq`.
- `schema_for` has an explicit arm per current `ModelFamily` plus a wildcard for
  the `#[non_exhaustive]` enum (canonical).
- `Sha256Digest::of_text` hashes the UTF-8 bytes in r-7 (no CR normalization yet).
- `TimestampMs` clamps a time before the Unix epoch to the epoch and a time after
  year 9999 to its last millisecond.
- Wire bodies are built as `String` (`serde_json::to_string`); the test-util
  `TruncateBody` fault cuts at a char boundary.
- Release input: `sc-decision-schema` added with `publish_order: 2`; later crates
  shifted by one. The parent runs `install.py`; `cargo publish --dry-run` of a
  dependent crate cannot resolve `sc-agent-types` from crates.io before the
  CPR-014 publish gate lifts, so only the kit dry-run script covers it.
- Status stays `in-review` (task XML); the coordinator flips it to `complete`
  after QA-2.
